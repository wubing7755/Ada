# 重构方案文档模板

配合 `engineering-refactoring` 技能使用。当用户要求"先出方案确认后再执行"时，在 `docs/refactoring/` 下按此模板创建方案文档。

## 结构

1. **头部**: 状态/日期/分支/前置/约束
2. **背景**: 为什么重构、引用质量报告、当前数据
3. **工程质量标准**: 类设计/成员设计/XML文档/参数验证/异常处理/测试规范 — 6 个维度统一定义
4. **Phase 详情**: 每个 Phase 含 目标→状态分析→设计方案→文件清单→验证标准
5. **依赖关系图**: ASCII 图展示 Phase 间依赖
6. **影响范围总计**: 表格式汇总
7. **参考文献**: 引用质量报告和已有实现

## 关键原则

- **全面性**: 不只写眼前 3 个 Phase，后续 Phase 也要列入（可简写）
- **依赖链**: 显式标注严格依赖 vs 可并行
- **验证标准分层**: "编译与测试" + "架构/质量"
- **质量基线**: 在方案开头统一定义，后续 Phase 引用
- **文档先行**: 确认后执行，不在执行中改方案

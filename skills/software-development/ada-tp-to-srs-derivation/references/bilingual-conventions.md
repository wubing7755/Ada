# 中文环境的双语约定 (Chinese-English Bilingual Conventions)

在中文技术协议（TP）→ SRS 派生场景中，文档正文和需求内容采用中英双语混合约定。以下表格定义了每种文档元素使用的语言。

## 语言分配表

| 元素 | 语言 | 说明 |
|:----:|:----:|------|
| §1~§2 正文 | 中文 | 产品描述、术语定义 |
| 需求标题/描述 | 中文 | 行为描述 |
| AC 场景名称 | 中文 | 如「AC1：显示登录界面」 |
| Given/When/Then | 英文 | 取决于团队约定，本技能继承的实践中为英文 |
| 术语表 | 三列 | 中文 \| 英文 \| 定义 |
| Actor 角色名 | 英文 | 如 Application Developer |
| 需求来源标注 | 中文 | 如 `> **来源**: TP §1.2` |

## 约定的由来

- **中文为主**：因为 TP 原文是中文技术协议，SRS 的目标读者（开发团队、验收方）也是中文环境
- **Given/When/Then 用英文**：这是 BDD（行为驱动开发）的国际通用惯例，便于工具链支持和跨团队协作
- **Actor 用英文**：角色名作为标识符使用英文，与 BDD 工具链保持一致；在需求 Description 中可以用中文描述角色

## 常见格式问题

### Given/When/Then 语言混用

**症状**：同一文档中有的 AC 用英文、有的用中文。

**对策**：在 §1 文档约定中明确约定，全文统一。编写完成后用正则扫描所有 AC，检查 Given/When/Then 是否使用了非英文内容。

### 术语表格式

术语表采用三列表格，列顺序固定为「中文 | 英文 | 定义」：

```markdown
| 中文 | 英文 | 定义 |
|:----:|:----:|------|
| 线型 | Line Style | ... |
```

不要在术语表中混用纯中文或纯英文的条目格式。

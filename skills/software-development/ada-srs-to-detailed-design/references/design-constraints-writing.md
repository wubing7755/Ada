# 设计要求及约束 编写规范（验收判据）

来源：目标项目 设计工具项目详细设计优化会话。实测 66 处约束中 52 处（79%）与 SRS Description 相似度 >0.8，24 处 1.00 一字不差——"设计要求及约束"是照搬重灾区，必须按本规范重写。

## 定位

设计要求及约束 = **设计约束（验收判据）**。回答"该设计**必须保证什么、不得违反什么**"；
不回答"需求要求什么功能"（那是需求层的事）；
不回答"怎么实现"（那是设计描述的事，机制细节如临时文件、命令封装不写进约束）。

## 四类填写内容（按优先级）

| 类型 | 含义 | 示例 |
|---|---|---|
| ① 行为边界约束 | 必须保证/不得违反，**含失败与异常路径** | "打开失败路径不得修改当前编辑会话" |
| ② 判定性约束 | 可验证判据 | "生成结果必须仅包含当前配置存在的条目" |
| ③ 一致性约束 | 跨文件/跨条目一致 | ".c 与 .h 条目数量及索引范围必须一致" |
| ④ 机制性硬约束 | 必须强制的机制（需求或安全性要求时） | "删除/覆盖前必须经用户确认" |

**不填写**：需求 Description 的"应支持 X"式功能声明（照搬）；设计描述已说明的实现机制细节。

## 句式

- "必须/不得/应保证"判定式；每条 1~2 句，1~3 条，简洁
- 主语同设计描述规范：资源工具/子工具，无内部组件名
- 约束与设计描述允许主题重叠（同一件事），角色不同：约束=判定条件（"必须满足 X"），设计描述=实现机制（"通过 Y 机制实现 X"）

## 照搬检测方法

约束正文与对应【需求来源】的 SRS Description **去空白后**做 difflib.SequenceMatcher 相似度：

- >0.8 = 基本照搬，需重写
- 1.00 = 一字不差（实测 24 处）

自动脚本：`scripts/check_constraint_copy.py <srs.md> <design.md> [阈值=0.8]`。
注意正则要同时匹配 4 级（`#### 5.1.1.1`）与 5 级（`##### 5.1.2.1.1`）约束标题，否则漏 SD-1 类条目；SD-2/SD-3 共用一个约束小节时按小节计，勿按条目数硬对齐。

## 七类行为骨架的约束句式模板

| 行为 | 约束模板 |
|---|---|
| 新增 | 新增条目必须立即显示于条目列表并可编辑，必须具备可识别的默认配置；新增操作必须可经撤销机制回滚。（图像/字体可加"初始可处于未绑定文件的待导入状态"；符号加"含默认标识与空图形元素集合"） |
| 删除 | 删除前必须经用户确认；确认后必须移除条目及其关联数据并更新显示，删除操作必须可经撤销机制恢复，取消确认时条目必须保持不变。 |
| 修改 | 修改值必须写入条目对象并进入编辑会话数据源，参与后续配置检查、保存与资源生成；修改必须记录修改前后值以支持撤销重做。（更换文件类加"更换必须经重新导入/有效性检查"） |
| 索引/标识分配 | 默认索引/标识必须取自当前未被使用的值，且分配结果须稳定可预期；分配仅初始化新条目，不得保证最终唯一性。（线宽另加"索引分配必须独立于线型条目"） |
| 预览/显示 | 预览必须依据条目当前配置，配置修改或条目切换后必须自动更新；预览规则必须与生成规则一致。（未绑定文件类加"必须显示待导入提示"） |
| 校验 | 检查必须覆盖缺失、为空及超出有效范围情形；存在无效配置时，必须标识问题条目并阻止对应资源生成。 |
| 生成 | 生成结果必须仅包含当前配置存在的条目，数据与索引必须一一对应；.c 与 .h 的条目数量及索引范围必须一致，生成内容必须满足 目标项目 Server 集成格式要求。（字体/符号加"失败条目与配置中不存在的条目不进入生成结果"） |

## 实例对照（本会话 5.1 公共模块）

- **SD-2** 旧（0.98 照搬）→ 新：打开操作必须依次通过文件存在性、读取权限与路径有效性校验；文件类型无法识别或与当前子工具不一致时，必须终止解析；整个打开过程不得修改当前编辑会话内容。
- **SD-13** 旧（1.00）→ 新：条目列表与属性区显示内容必须与编辑会话数据一致；条目增删改及撤销重做后显示必须自动更新，显示过程不得修改配置数据。
- **SD-56** 旧（1.00）→ 新：放置操作必须显示于编辑区域并加入当前符号条目的图形元素集合；放置必须可经图形元素撤销/重做恢复，放置过程不得改变图元库配置及其他符号条目。
- **SD-67** 旧（1.00）→ 新：停用元素前必须扫描全部符号条目并识别受影响元素，呈现影响范围；调整必须经用户确认后生效，取消时图元库配置必须保持原状。

## 关联：设计描述的通配性（SD-58 教训）

需求保持通配（"根据图形元素的类型"）且元素类型由图元库配置决定时，设计描述与约束都**不得枚举固定类型集合**（如把几何属性写死为点/线/圆弧/椭圆/三角形五种的属性映射）。按需求维度的类描述："几何属性按位置、尺寸与形状三类组织……属性集合与图元库中该元素类型的定义一致，不固定绑定特定元素类型"。

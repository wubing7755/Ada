# 设计描述质量审计 — 骨架表与实例（多进程 目标项目 2026-08 会话）

配套 SKILL.md「同类条目对称性审计」一节。本文给出完整骨架表、审计流程实例、以及本次审计的真实发现与误报甄别。

## 审计流程（五步）

1. **建骨架表**：7 类行为 × 必须覆盖要素（下表）。
2. **自动关键词检查**：每要素配关键词/正则，逐条扫描【设计描述】块，输出缺失要素清单。注意只扫描述块，不扫组件表/需求来源。
3. **人工甄别误报**：自动检查必出两类误报（见下），逐条人工核对后再定性。
4. **按问题模式归类**：同类缺失合并为问题模式（如"修改类 3 条缺即时校验策略"），输出审计报告，不逐条零散报。
5. **同类一起修复**：按模式批量修，保证对称性一次到位；修复后重跑验证（编号连续 + 残留检查 + 追溯）。

## 本次审计真实发现（问题模式清单）

1. **修改类缺"即时校验策略"（3 条，实质缺陷）**：SD-22 线宽、SD-38 图像、SD-46 字体缺"修改不进行即时校验拦截，保留用户输入"；对照 SD-16/30/54 有此句。修复：补齐，与同类对齐。

3. **删除类"确认提示意图"措辞不对称（5 条，措辞级）**：SD-15 有"避免误操作"，SD-21/29/37/45/53 无。修复可选：统一补或统一删。

## 自动检查的两类必出误报（人工甄别）

- **关键词缺"依据" ≠ 缺绘制依据**：SD-40 图像预览无"依据"二字，但有"优先按原始像素数据渲染"；SD-48 字体预览有"按条目当前绑定的字体渲染字形外观"——绘制依据均在。关键词表要覆盖同义表达。
- **名称含"有效性检查" ≠ 生成前校验规则**：SD-49 TTF 导入与有效性检查是**导入时文件校验**（REQ-F-299），不是生成前配置检查规则（SD-19/25/33 那类），不需要"注册执行/阻止生成/重算"要素。骨架分类按语义，不按名称。

## 解析陷阱（validate_sdd.py 已修复）

- SRS 需求条目整体包在 ``` 代码块内，Source 字段行 `REQ-F-062（可编辑文件管理）` 是**父需求（研发需求）引用**，不是实现需求——正则必须整行锚定 `^REQ-F-\d+$`，否则把 29 个研发需求误算进实现需求（120 vs 91），"漏设计"检查全部误报。

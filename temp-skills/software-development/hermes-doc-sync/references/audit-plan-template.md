# 审计计划模板

> 用于"外部文档对照审计"工作流 (SKILL.md → 工作流 B, Step B4)

## plan.md 结构

```markdown
# <项目名> 增强计划

> 来源: <权威文档名> 与当前项目对照审计
> 目标: <一句话目标>
> 创建日期: YYYY-MM-DD

## 总览

| 优先级 | 阶段 | 改动文件 | 工作量 | 说明 |
|--------|------|----------|--------|------|
| P0 | Phase 1 | <文件> | 中 | <描述> |
| P1 | Phase 2 | <文件> | 小 | <描述> |
| ...

## Phase 1: <标题>

### 1.1 <具体改动1>

**位置**: <文件> §<章节>

**内容**: <新增/修改内容描述>

### 1.2 <具体改动2>

...

## Phase N: <标题>

...

## 实施约束

1. 不删除现有内容 — 所有改动以新增和补充为主
2. 保持文档架构 — <列出架构约定>
3. 更新 EVOLUTION — 每 Phase 完成后记录
4. 更新 <入口文档> 头部日期

## 验收标准

- [ ] <可验证的标准1>
- [ ] <可验证的标准2>
- [ ] EVOLUTION.md 记录本轮全部改动
```

## 格式要点

- 每个 Phase 应列出:**改动文件 + 具体位置（行号/插入点）+ 改动内容**
- 优先级用 P0/P1/P2 标注，对应 🔴/🟡/🟢
- 验收标准应是可验证的布尔条件（"场景数从 14 增至 16"而不是"场景数足够多"）
- 如果改动涉及章节编号偏移，在 Phase 最后单独列一个"编号级联修正"步骤
